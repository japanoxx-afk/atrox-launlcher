# Atrox Launcher

게임 경로와 화면 설정을 한 화면에서 관리하는 Windows 런처입니다. 지원하는 `Atrox.ex_` 원본을 확인한 후 게임 실행 파일을 매번 새로 패치합니다. 게임 원본은 이 저장소에서 배포하지 않습니다.

- v1.6.0: F2 전투 유닛 전체 선택 및 `.` 유휴 일꾼 전체 선택을 추가합니다. 전체 선택은 최대 128마리이며, 이동·공격·정지 명령을 기존 18마리 명령 목록으로 나누어 처리합니다. 확장 선택의 하단 초상화는 16마리까지만 표시하며, 일반 드래그 선택 및 기존 부대 지정의 18마리 제한은 유지합니다. 확장 선택은 사용자 실게임 검증으로 정상 동작 확인했습니다.
- 생산 유닛은 랠리 방향의 빈 출구를 우선 사용합니다. 여러 유닛의 에너지 마법은 명령마다 시전 가능한 한 유닛을 순서대로 선택합니다. 이 두 기능의 자동 테스트는 통과했으며, 별도 실게임 검증은 아직 완료하지 않았습니다.
- 저장 게임 불러오기 시 지도 식별 정보가 초기화되지 않아 지도 검색에 실패하고 종료되는 오류를 수정했습니다. 같은 이름의 지도 파일이 하나의 식별값으로 확인될 때 복원하며, 서로 다른 지도 버전이 있으면 임의로 선택하지 않습니다. 초기화되지 않은 화면 목록의 정리 오류도 방지합니다. `ddd` 저장 게임 불러오기 성공을 확인했습니다.
- 확장 선택의 선택 상태는 저장 게임에 별도로 보관하지 않습니다. 불러온 뒤 F2 또는 `.`을 다시 누르세요. 멀티플레이 참가자는 같은 런처 버전을 사용해야 합니다. 새 리플레이에는 확장 선택 규칙 표식을 기록합니다.
- v1.5.0: 오지·네일러의 건물이 완공되면 건설 일꾼 1마리를 반환합니다. 오지의 건설 가속 추가 투입은 기존 최대 2마리 제한을 유지하며, 완공 시 추가 투입분도 반환합니다(총 최대 3마리). 출구가 막혀 있으면 게임 틱마다 빈자리를 다시 찾습니다. 반환 대기 중 건물이 파괴되거나 경기를 종료하면 대기분은 제거되며, 대기 상태는 저장 게임에 기록되지 않습니다.
- 새 건설 규칙은 시뮬레이션을 바꾸므로 멀티플레이 참가자는 같은 버전을 사용해야 합니다. 새로 저장하는 리플레이에는 규칙 표식을 기록하며, 표식이 없는 기존 리플레이는 기존 건설 규칙으로 재생합니다.
- 실제 검증: 네일러 완공 후 반환 확인, 오지 완공 및 추가 투입분 반환은 사용자 실게임 검증으로 정상 동작 확인.
- v1.4.1: 리플레이 재생 중 양쪽 플레이어의 탐색·현재 시야를 합쳐 표시합니다. 미탐색 값(0x8000)을 가시 상태로 잘못 합쳐 화면 전체가 검게 되는 v1.4.0 오류를 수정했습니다. 실제 경기의 시야·동맹·명령 데이터는 변경하지 않습니다.
- 리플레이 자동 저장 옵션: 기본 켜짐, 최대 20개(1~1,000개 선택). 게임이 정상적으로 경기 기록을 마무리할 때 `Atrox\Users\사용자명`에 `AtroxAuto-날짜-시간-밀리초-번호.rec`로 저장합니다. 해당 형식의 자동 저장 파일만 오래된 순으로 정리하며 수동 저장은 보존합니다. 강제 종료·충돌 전의 기록은 보장하지 않습니다. 저장 결과는 게임 폴더 `AtroxReplay.log`에서 확인할 수 있습니다. 옵션은 다음 게임 실행에 적용됩니다.
- v1.3.7: 어두운 테마로 화면을 재구성하고 이메일 표기 및 사용자 정의 시나리오 선택·설치 기능을 제거했습니다. JPak 옵션은 유지합니다.
- 1280x1024에서 하단 HUD 양쪽에도 지형과 게임 오브젝트를 그립니다. 지형 캐시 높이와 스크롤 경계 복사를 수정해 검은 가로줄 및 잔상을 방지합니다.
- 확장 해상도의 건설 미리보기 입력 판정을 수정했습니다. 원래 800x600 화면의 하단 경계(Y=486)가 확장 영역을 가리지 않도록 하고, 실제 HUD 위의 입력 제한은 유지합니다.
- 생산 건물의 랠리를 뮤온에 지정하면 오지·네일러·엔지니어에게 게임의 기본 채취 명령을 전달합니다. 일반 유닛이나 자원이 없는 지점은 기존 이동 명령을 유지합니다.
- 화면 이동 속도는 기본 10%이며 5~100%를 선택할 수 있습니다. 속도 변경은 다음 게임 실행에 적용됩니다.
- Alt+Enter로 창 모드와 모니터 전체를 채우는 테두리 없는 전체화면을 전환합니다.
- v1.3.3 최초 실행 시 이전 속도 설정은 10%로 조정됩니다. 이후 선택한 속도는 유지됩니다. 전체화면에서는 가로·세로를 각각 늘리므로 원본 화면 비율이 달라질 수 있습니다.
- 런처 업데이트 버튼은 GitHub Release의 실행 파일과 SHA256을 검증하여 적용합니다.

화면 출력은 MIT 라이선스의 [cnc-ddraw v7.1.0.0](https://github.com/FunkyFr3sh/cnc-ddraw/releases/tag/v7.1.0.0)을 포함합니다. 최초 실행 시 게임 폴더에 `ddraw.dll`, `ddraw.ini`, 라이선스를 설치합니다. 기존 출력 모듈 및 설정은 해시가 포함된 `.before-launcher-*` 파일로 보존합니다. 기존 게임 데이터, 저장 파일과 원본 런처는 유지합니다.

## 빌드와 검증

Windows 및 Visual Studio MSBuild, C++ x86 빌드 도구와 Windows SDK가 필요합니다. 빌드 시 리플레이 모듈과 네이티브 회귀 테스트도 함께 컴파일·실행합니다.

```powershell
./build.ps1
./tests/verify.ps1
./tests/verify-replay.ps1
```

결과는 `dist/AtroxLauncher.exe`입니다. 검증은 설정 경로 해석, 배포 체크섬, 두 축의 속도 패치, 지형 캐시와 전체 높이 설정 및 원본 코드 불일치 차단을 확인합니다. 선택적으로 x86 명령 실행도 검증할 수 있습니다.

```powershell
$env:ATROX_EXPORT_PATCH = "$PWD\artifacts\terrain.bin"
./tests/verify.ps1
python -m pip install unicorn
python ./tests/verify-terrain.py
python ./tests/verify-scroll.py
python ./tests/verify-gameplay.py
```

명령 실행 검증에는 로컬의 지원 원본(`~/Downloads/AtroxLauncher/Atrox.ex_`)과 Unicorn이 필요합니다. 게임플레이 검증은 HUD 입력 경계의 실제 x86 코드와 랠리 명령 변환을 실행합니다. 랠리 대상 검색 및 RTTI 판정은 모의 함수이므로 실제 게임 내 채취 확인도 필요합니다.
